## 挂载修正身份与异常退出复核（2026-10-19）

复核 `6510d7f` 对应的私有恢复维护脚本，合成环境确认两处问题：修正器没有使用观察中已有的 mount ID，目录设备号/inode 相同但挂载已被替换时，仍会修改新的挂载；子进程超时只终止调用主进程，后代进程仍能稍后执行操作。反例仅使用新临时目录及独立挂载命名空间，没有修改实际业务目录。

修正器现在要求准确命名空间、mount ID 和目录身份同时匹配，通过保留的 O_PATH 描述符指向所选挂载，并禁止 remount 工具把描述符重新规范化为可能已经改变的路径。前后核对路径身份和原有 VFS 属性；缺少或失效的 mount ID 在操作前拒绝。检查后路径被另一挂载遮蔽的合成竞争中，只对原选定挂载增加只读约束，新挂载保持未动，结果仍报告未确认，不能把原挂载已只读冒充当前路径已隔离。
