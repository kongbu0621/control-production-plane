# P／K／Ledger 组合恢复核对

组合恢复需要回答：恢复的 P 原任务、K 原使用及知识状态、Ledger 准确版本的材料能否对应，以及这些副本现在可以做什么。

目前提供[安装态组合恢复演练](../tests/installed_combined_recovery.py)，验证下述五个窄场景。Ledger 有正式快照接口；P、K 尚无组合备份、路径迁移或副本启用接口。本文是操作规程及验收范围，不把一次合成演练称为真实数据切换完成，也不授予恢复副本新的执行资格。

## 组件与组装的职责

| 负责方 | 在恢复过程中负责什么 |
| --- | --- |
| P | 保留原运行、修订、尝试、请求、知识调用及未知提交；恢复回执、查询原任务，不重放结果未知的业务 |
| K | 保留准确使用和审查回执、版本及生命周期；通过公共接口报告当前对象和材料观察 |
| Ledger | 创建、验证和恢复准确快照；按材料原引用核对身份、版本和实际字节 |
| 组装操作 | 核对兼容安装、所选恢复点及相互引用，保留备份之外的已知后续决定，确认全部原写入者停止或隔离，明确哪个实例可接续什么操作 |

取得新目录的锁只排斥这个目录的其他 P 推进者。原目录与副本的锁是不同文件，两者可以同时取得；K 的 SQLite 锁也不能约束另一份数据库。恢复点相同、路径可打开、摘要完整和旧副本显示 ACTIVE，都不能证明原写入者已经退出或没有后续决定。

## 已验证的五个窗口

| 场景 | 演练步骤及应得到的结果 |
| --- | --- |
| K 已成功，P 尚未确认 | 子进程在 K 提交后、P 的 `knowledge_ack` 前实际退出。保留原 P pending 和成功 K 回执；冷副本与 Ledger 恢复后，`resume` 补记同一回执。原任务 ID、额度不变；K/Ledger 文件摘要不变，重复恢复不新增 P 记录 |
| Ledger 恢复点较旧 | 用同一 Ledger 的早期快照恢复，锚点仍存在但材料缺失；K 如实报告材料不可核对，P 提交返回 `KNOWLEDGE_UNAVAILABLE`，动作保持 QUEUED，不调用业务、不花业务额度。换回包含材料的准确快照后，同一原版本可重新只读核对 |
| K 快照遗漏后续退休 | 旧 K 包含原使用、回执和完整材料，P 当前状态检查仍读到 ACTIVE。将独立保留的后来退休回执与该副本的 `get_operation` 对照，可发现缺失；该副本仅供历史核对。完整副本保留原退休回执，当前检查返回 `NOT_READY` |
| P 已登记提交，回应未知 | 产生一次合成外部效果后丢失响应，再恢复组合副本；P 指向原任务查询，再次 `perform` 返回 `PENDING`，不产生第二次效果、不改写未知记录 |
| 原写入者仍在运行 | 真实子进程占用原 P 执行租约，原目录返回 BUSY，而已存在的冷副本仍能取得自己的锁。演练保持副本仅供历史核对，直到确认受控子进程退出且双流关闭；不把副本锁成功解释为生产隔离成功 |

“已知后续退休”和“原写入者仍在运行”这两项条件由演练协调步骤检查，**不是 P 当前库接口新增的自动隔离或抗回滚能力**。尤其是退休遗漏：如果后来决定及其来源也丢失，旧快照无法自行证明“没有后续退休”。缺少可核实的当前依据时，保留未知，不能仅从 ACTIVE 推出允许新执行。

## 恢复操作顺序

1. **保留原件并确定范围。** 记录所选 P/K/Ledger 安装载荷、完整目录、快照 manifest 摘要，以及 P 原运行/尝试/任务/请求、K 使用和准确版本。配置及完整材料保持私有；同一个包版本号不代替实际源码或 wheel 摘要。
2. **确认写入者状态。** 核对 P 推进者、K 其他消费者、Ledger 写入者，以及仍可能提交任务的 CLI 子进程。P 的执行租约不覆盖所有本地写命令，也不覆盖 K 或 Ledger。已提交的 Local Hand 原任务可能继续运行，不能从 P 退出推断任务停止。未知调用保留原身份，先查询。
3. **选择完整恢复点。** 使用 Ledger 的 `snapshot create / verify / restore` 及外部保留的准确 manifest 摘要。P/K 当前仅在确认停写、连接关闭的环境保留完整冷副本；不能把演练的 `copytree` 当作在线备份方法。SQLite 日志等原文件一并保留，不手工删日志或修改私有表。
4. **核对路径绑定。** K 保存 Ledger 的绝对路径及锚点。当前没有公共重新绑定接口；随意编辑身份文件或数据库不是迁移。演练只在全新合成域内，另存原 Ledger 目录后，向同一绑定路径下的全新目录恢复。真实环境需要先确定受支持的绑定位置和停止/隔离方式，不能照搬演练目录替换现有数据。
5. **先只读对账。** 用 P 的 `get_run`、`get_action`、`recover` 核对原意图；按 K 原 scope/operation/request_id 调用 `get_operation`，分别检查历史成功回执与当前对象/材料观察。核对原版本、使用对象及 Ledger 的准确材料引用和实际内容。引用完整不能替代恢复点的新旧核对。
6. **对照后续事实。** 用恢复副本之外保留的来源记录核对已知采用、反馈、修订和退休。新旧记录矛盾或后来回执缺失时，保留这份历史副本，找回正确恢复点。不要把旧 pending 的 NOT_FOUND 当作从未写入，在旧副本上重新发起写入来填平差异。
7. **按核对结果接续。** 原成功回执已存在时，可以沿原请求补记；新材料、采用或业务写入仍须确认目标实例及原写入者边界。已提交/结果未知的业务只沿原任务核对。新提交在当前知识检查及原取消、预算、权限约束下推进；没有明确的实例选择和隔离结果时，副本仅用于历史核对。

这些步骤不要求重做已经完成的任务或所有历史验收。只读核对失败可修正后重试；已有成功写入应复用原回执，不能换身份重做。单个成功回执也不证明整个数据域都已恢复到最新状态。

## 重复运行隔离验收

在独立 Python 3.12 环境安装已核对的 P `0.1.0a4`、K `0.1.0a2` 和 Ledger `0.2.0a1` wheel。使用满足 Ledger 快照要求的本地持久文件系统；脚本只接受 scratch 父目录，每次创建新的私有合成目录，没有真实存储、NAS、服务或部署参数。

```sh
/path/to/venv/bin/python -I -B tests/installed_combined_recovery.py \
  --scratch-parent /absolute/private/local-scratch \
  --ledger-source-commit FULL_LEDGER_SOURCE_SHA
```

`FULL_LEDGER_SOURCE_SHA` 替换为已核对安装载荷对应的 Ledger 完整 40 位提交 SHA。该值进入 Ledger 快照来源记录；脚本不会仅凭这个参数证明安装源码身份。按各仓安装方式核对 wheel 与源码，报告另外保存三包实际模块 SHA-256、包版本和演练脚本摘要。

成功需进程退出 0、五个场景全部通过，报告 `status=PASS`、`activation_performed=false`。每项结果、快照/恢复返回、原目录、冷副本、已知后续回执和 `report.json` 都保留在输出的工作目录；另存已核对的原回执确认状态、准确失败事件、退休状态及未知提交恢复观察。不能用任意文件变化、相同错误码或恢复建议文字代替实际身份和状态核对。

普通异常报告 `FAIL`，可捕获的中断报告 `INTERRUPTED`，记录出错的场景并保留已完成结果，后续修复另建目录。参数/语法错误可能尚未创建目录；强制结束进程、断电或报告写入失败可能没有完整报告。任何缺失或不完整报告都不能作为成功证据，也不自动重跑原任务。

演练子进程的退出码和 stdout/stderr 原始字节另存为对应场景中的 `adoption-child.json`、`writer-child.json`，字节以十六进制保存。就绪标记按同一单调时钟期限逐段读取，半行输出不会绕过超时。超时或失败时只终止并回收演练自己创建的子进程，保留已有输出；这项清理不属于真实生产写入者隔离。若进程或双流收集未能完成，仍以失败处理，不能补写退出成功。

演练自身的反例检查使用同一独立安装环境，故意返回错误事件、错误任务身份、未确认回执和不符的退休状态，并验证中断、失败报告、半行就绪超时及子进程异常输出保留。运行方式为：

```sh
/path/to/venv/bin/python -I -B tests/installed_combined_recovery_rejections.py \
  --scratch-parent /absolute/private/local-scratch \
  --ledger-source-commit FULL_LEDGER_SOURCE_SHA
```

该入口保留自己的全新合成目录；十项检查全部通过且进程退出 0，表示演练能拒绝这些反例并保留相应失败证据。其内部故意生成的 `FAIL`／`INTERRUPTED` 报告是反例证据，不能当作正常五场景验收通过。

这项验收使用真实 SQLite、公共库、Ledger 快照及子进程；业务执行响应为合成数据，未连接真实 Local Hand 或 NAS。它没有实现通用组装服务、生产副本自动启用、跨机隔离、P/K 在线快照或路径迁移，也不代表 Ledger A3 的其余消费者已验收。真实切换需要按上方规程落实所选实例、恢复点、绑定路径和写入者状态，并保留独立现场结果。
