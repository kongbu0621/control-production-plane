# 架构：控制过程与基础能力分工

状态：首版设计提案，与[需求](REQUIREMENTS.md)配套。下面的接口名称是职责名称，尚非已发布 API。

## 组成与依赖方向

首版拟使用 Python 3.12、Linux 和单用户 CLI，核心协调逻辑作为可导入库；CLI 与库共享相同操作语义。选择这个起点是为了复用已有 Local Hand 结果归档能力，不代表未来仅支持这一平台。

| 模块或端口 | 本仓负责的内容 | 外部事实或决定的来源 |
| --- | --- | --- |
| 控制核心 | 目标推进、尝试关联、修复条件、恢复顺序及预算 | 消费明确目标、执行观察和决定，不覆盖来源事实 |
| 运行记录端口 | 持久化本控制器的输入、待发动作、回执、观察及接续点 | 远端执行状态仍由执行后端报告 |
| 执行适配器 | 将已绑定方案转换为准备、提交、查询、取消和证据读取操作 | Local Hand 公共接口及其原任务账本 |
| 成果适配器 | 保存合格候选引用，按精确版本读回并核对 | 现有归档 CLI，经 Ledger 公共库接口保存内容 |
| 验收输入 | 关联来自指定验收者的接受、拒绝或需修复决定 | 首版为本机操作者明确给出的决定，不实现通用治理服务 |

依赖由控制核心指向端口，再由适配器调用公共接口。Local Hand 和 Ledger 不反向依赖本仓。外部应用通过本仓入口使用协调能力，不访问内部数据库表。

首版采用显式配置的静态适配器。尚未出现实际复用需要的模块先留在仓内，不能为了抽象完整而提前创建 Hub、契约发布服务或更多仓库。

## 目标、运行和尝试

- **目标与验收条件**：固定版本和内容绑定，说明期望结果；修复不得静默降低标准。
- **计划修订**：绑定输入、来源、执行能力、验证方式及预算。改变方案形成新修订，保留历史。
- **运行**：推进同一目标的过程，拥有稳定的本地运行 ID。
- **尝试**：一次具体业务执行，关联计划修订和独立的 Local Hand `operation_id`。对同一尝试恢复查询时复用原任务 ID 与请求。
- **成果引用**：明确 Artifact ID、Version ID 及其来源尝试，不提供隐式“最新成果”选择。
- **验收决定**：绑定目标、候选版本和依据；声明者、时间和原因可追溯，不冒充外部已认证签名。

核心分别保存“控制推进到哪里”“执行后端观察到什么”“验证得到什么”“验收者决定什么”。不能用一个成功布尔值覆盖这些不同结论。公共状态枚举将在实现时按实际接口定义，不把这里的说明当作已冻结的通用运行合同。

## 持久化与副作用

首版拟由仓内运行记录模块独占一份本地 SQLite 数据库，保存本控制器的协调记录。它不读取或修改 Local Hand、Ledger 的私有表，也不成为远端进程状态的新权威。

该模块是未来运行记录组件的候选接入位置；尚未实现独立的 `infra-runtime-ledger` 服务，也不宣称本仓实现了其完整规划职责。未来替换必须迁移原身份、未决动作和历史记录，不建立两套可各自修改的运行事实。

一次可能有副作用的调用按以下顺序推进：

1. 在本地持久保存精确输入、绑定、原任务身份和待发动作。
2. 调用外部公共入口。
3. 保存回执或失败；没有确定回执时保留未决状态。
4. 恢复时先读取待发动作，查询同一外部任务或原写入结果，再决定是否能继续。

本地数据库和远端操作不构成跨系统事务。进程在任一边界退出，都不能通过本地“未记成功”推出远端“没有执行”。执行适配器的去重、查询与来源绑定是恢复依据。

同一运行只允许一个推进写入者，使用进程级互斥和数据库事务；查询不隐式推进业务。竞争、损坏或不支持的存储版本应显式报错，不自动覆盖或新建替代存储。状态目录、证据和凭据保持私有，日志不回显密钥。

## Local Hand 适配

首版优先通过已安装的公共 CLI 和其 Unix socket 接入，不要求为本仓更换现有管理服务或新增 MCP 工具。能力来自实际部署，源码中有某功能不等于当前服务已开放。

| 公共工具 | 本仓使用方式 |
| --- | --- |
| `lh_capabilities` | 核对已开放任务类型、来源和验证引用 |
| `lh_workspace_read` | 读取获准来源文件及绑定信息，核对原内容 |
| `lh_job_prepare` | 保存新任务 ID 后准备任务；沿原 ID 与参数接续准备 |
| `lh_job_submit` | 提交原准备结果中的请求，保存原请求摘要 |
| `lh_job_status` | 查询原任务，区分执行、业务及证据状态 |
| `lh_job_cancel` | 针对原任务及请求摘要申请取消，随后继续核对退出 |
| `lh_evidence_manifest`、`lh_evidence_read_chunk` | 完整读取清单与分块，核对大小、摘要和封存绑定 |

`workspace.edit` 在独立任务副本中修改单文件并运行固定验证，返回补丁、前后内容及验证输出。控制组件不将其解释为原工作区已改变；本阶段不调用本地应用入口。

当前常驻入口不提供通用的 `lh_job_reconcile`。控制进程的恢复是读取本地接续记录并查询原任务，不假定能够通过未开放工具修复远端任意状态。需要后端维护时保留具体缺口，不靠重新提交绕过。

## 成果归档和真正使用

首版复用 `local-hand-archive archive / read / resume` 作为成果适配器，而非重写已存在的归档协议。该工具在内部使用 Ledger 公共接口；本仓不直接写它管理的 `ledger.sqlite`。

归档输入必须来自真实认证的状态响应和对应证据，可信摘要在接收时保留。对任意文件自行算一个摘要不能证明其来自指定执行器。只有满足现有 `SUCCEEDED / SEALED` 条件的任务才能走成功候选归档；失败任务的观察和现有证据另行保留。

归档返回的 Artifact/Version 引用写入运行记录。后续审查通过 `read` 读回精确版本，使用读回的补丁、前后内容和验证报告判断是否满足目标，并记录使用了哪个版本、得到什么结论。读取输出使用新目录，不覆盖既有成果。

`archive` 的创建身份与追加版本是分开的 Ledger 事务；非零退出不能推断全部回滚。丢响应使用原 producer 和 operation ID 进行 `resume`，保留整个归档目录，不重新生成一套身份。业务已完成时归档重试不得触发业务重跑。

默认存储为满足现有归档工具要求的本地持久文件系统；不能把归档工作目录放到 NAS 或共享目录。Ledger 的快照恢复属于独立能力，本首版不重做已完成的 A2 现场任务。

## 修复、取消与资源

首版修复方案由调用方提供。只有原执行已确认停止、结果已明确、原目标和预算允许时，才形成新的业务尝试；失败或验收拒绝不会覆盖前一尝试。

普通本地校验失败与只读连接错误可修正或有界重试。业务结果未知时进入待核对状态；之后出现可验证新信息可继续，不把一次失败永久锁死。取消请求持久化后继续查询；时间预算耗尽也不能把仍在运行的任务记为已经退出。

尝试次数、总时限、单次调用时限、读取大小和磁盘预算在首次副作用前明确。预算耗尽停止新下发并保留查询与取消所需记录；失败重试不能绕开预算。具体默认值随真实适配限额确定，不用无限值掩盖未设计资源约束。

## 验收与未来扩展

首版用明确的本机操作者输入承载验收决定；CLI、测试输出和控制核心不能自行授予其额外权限。后续正式授权、证据准入和生产验收服务通过各自端口接入，分别拥有其决策职责。

知识读取、候选学习记录、可替换执行器和本地/云端部署是后续扩展方向。首版保留调用边界和可追溯输入，暂不发布未实现的知识接口、不引入旧整体原型作为运行宿主，也不以接口存在宣称可替换性已验收。
