# 首版实施计划

状态：运行记录核心、Local Hand/Ledger 静态适配及验收记录已实现，提供可安装的库与 CLI；合成链路验证与现场接续点见[开发记录](DEVELOPMENT.md)。第 2 步及第 4 步已有一次真实 README 候选完成执行、归档、准确版本读回和 ACCEPT；第 3 步已验证 P 响应落账前中断恢复、准备阶段取消、业务启动前及真实 helper 运行中取消、完成后取消保留原结果；原任务盘容量阻塞经批准扩容后已解决。运行中取消的业务结果仍为 UNKNOWN，退出已证实；其他中断和竞争窗口仍须分别验证。候选验收不包含应用到原工作区。

## 当前输入

目标与边界见[需求](REQUIREMENTS.md)，模块和恢复语义见[架构](ARCHITECTURE.md)。源码核对基线和既有决定见[开发记录](DEVELOPMENT.md)。这些源码基线不证明现场已经安装相同版本；执行适配时必须核对实际入口和能力。

实施顺序以尽早取得一项真实任务的可恢复闭环为准。首次写入前具备身份保存、权限核对和重复执行保护；后续阶段补齐同一范围的故障路径，不先建设通用平台。

## 1. 明确入口并实现最小运行记录

建立独立 Python 包、核心库和 CLI。具体包名、命令和 JSON 形状随首个实现提交写入公共接口文档，避免 README 展示不存在的命令。

先支持创建目标与计划、查看运行、保存待发动作和恢复原运行。运行数据库和私有状态目录由调用者显式选择；定义格式版本、单写入者约束、本地请求幂等，以及输入、部署/调用主体、归档实例和事件的不可静默改写规则。初始化与打开现有存储分开。

在首次真实下发前，完成取消意图与提交的互斥屏障、待决调用/子进程的接续、业务额度预留和只读核对预算。用替身演练关键中断点，不能把这些保护全部留到第三步再补。

区分执行者占用与短时状态事务；等待外部响应期间必须允许登记取消和读取状态。旧子进程/管道状态不明不阻断原任务的有界只读查询。验收以“外部调用仍挂起时能保存取消意图、无第二次业务下发”为准，不能只检查锁存在。

同时定义可选知识读取与学习候选出口的最小数据边界，并提供明确的未配置行为；此处不建设知识服务。知识版本和来源、候选与运行证据关联必须能通过接口测试，避免以后重写核心数据模型。

验收：独立进程读取同一记录；在提交意图写入前后中断，能准确区分本地未准备完成与外部结果待查询；两个推进者不能重复下发。测试应观察持久化结果和调用次数，而非只检查内部函数被调用。

## 2. 接通现有执行入口与成果适配器

只读核对实际 Local Hand 入口、开放能力、已登记项目和固定验证。复用现有安装与配置，遇到具体缺口再修复；不把升级服务或新建插件作为前置。

接入准备、提交、状态、取消和完整证据读取。按实际准备状态轮询原 `lh_job_prepare`，提交后才查询原任务状态；验证 `READY` 请求的原样保存、过期处理及禁止用一次 `NOT_FOUND` 推断无执行。

符合条件的候选通过现有 `local-hand-archive` 保存，再按准确 Artifact/Version 引用读回。将 source 与本运行的任务、请求及 workspace 输入逐项核对，保存使用版本和实际内容摘要，使归档真正进入业务流程。

同时覆盖读回目录发布后的响应丢失：保留原输出，按同一版本在新目录重新取回并核对，不能删除重用原路径。接纳前失败允许的重新准备保存新旧请求修订；不能把保留不可变历史误写成永久禁止换用服务返回的新 READY 请求。

验收：在独立环境中安装所选包，经实际公共入口完成一次新任务，并证明后续审查读取的是指定归档版本的实际内容。归档失去响应后只恢复原写入，不重跑已完成任务。

## 3. 完成修复、验收及恢复边界验证

在同一目标下接收修订方案，保留旧尝试、原要求和资源预算。原执行尚未停止，或外部副作用仍未核实时禁止启动替代写入。对仅写任务独立副本的 workspace.edit，可信维护者可以经 confirm_stopped 保存准确身份、未来启动封锁及进程树/写入者退出证明；旧 UNKNOWN 与预算保留，再以独立明确的运行和授权预算继续同一目标。此例外不放行任意外部副作用，也不重新开放旧业务提交。实现本机操作者明确提交的验收决定及其与目标、候选版本和依据的绑定。

在第一步保护和第二步适配基础上，补齐真实运行中取消、准备中停止推进、任务先完成的取消竞争以及控制进程重启验证。恢复沿原身份查询，不等同于启动一个新任务；证据暂不可得时保留执行结果与证据缺口。

验收关联已核对的读回收据和逐项条件依据，覆盖重复提交与旧候选决定迟到。知识接口验证未配置、无匹配、查询失败和版本绑定；学习候选验证来源完整、接收/准入分离、发送失败可接续且不重跑生产。未连接真实知识服务时只报告端口验证。

验收：可定位失败原因、修订输入、新旧尝试和最终决定；已完成任务只读返回。取消请求已接收但退出未证实时保持待核对状态。

## 4. 完成安装态试点和用户文档

选择已有需求中的真实软件任务，不新建无关示例项目，不重放历史任务。试点前核对目标来源、能力引用、授权、预算和成果目录。目标未登记时报告具体阻塞及必要配置，不猜测目标或扩大权限。

补齐安装、使用、公共操作列表和恢复说明，执行相关编译与打包检查，再从独立安装环境验证实际导入来源及 CLI 行为。演练数据和原始证据保持私有，公开记录只包含可披露的版本、验证方法、结论和限制。

首版交付说明分别列出功能完成、适配验证、真实任务结果和仍未测边界。完成此试点不自动宣告 Ledger A3 全部完成，独立 Generic Agent 消费仍须自己的真实证据。

## 重点验证矩阵

| 场景 | 应观察到的行为 |
| --- | --- |
| 原来源或内容摘要不匹配 | 下发前拒绝，不覆盖目标或猜测新基线 |
| 准备丢响应、`PREPARING` 或可修正的 `FAILED` | 原参数接续准备；重试不改 inputs，不把准备轮询误用成已提交状态查询 |
| 提交丢响应、查询暂为 `NOT_FOUND` | 保留未决调用，核对原身份与去重条件，不新建任务重放；同一尝试不重复业务 |
| 控制进程在外部调用前后退出 | 保留原意图与回执缺口，重启不盲目重放 |
| 同一运行被两个进程推进 | 只有一个写入者获得推进权 |
| 外部 CLI 挂起时收到取消 | 短事务能及时保存取消意图；等待 I/O 不占用状态写锁，无第二个执行者重复下发 |
| 控制器已退出、CLI 子进程仍可能运行 | 不将锁释放或超时当作所有调用已结束，不盲目重发 |
| 原调用退出证明或管道 EOF 丢失 | 原身份只读查询仍能进行；保留采集缺口，不放开重复副作用 |
| 部署/主体变化，或运行记录缺失、回退 | 拒绝静默改绑定或空库重建，不将旧的未提交状态当当前事实 |
| 本地创建/修订/决定写入后丢回执 | 原请求 ID 与内容重试返回原结果，同 ID 不同内容拒绝 |
| 本地预检、只读请求失败 | 修正原因后可继续，不误报远端已执行或永久封锁 |
| 原业务失败、修复后继续 | 原记录保留，新尝试显式关联且受预算限制 |
| 任务副本的业务未知，但维护已证实原写入者退出 | 独立保存准确绑定的停止证明；旧 UNKNOWN、调用和预算保持原样，新运行仍核对已有授权范围与明确预算 |
| 取消已受理、进程未退出 | 不报取消完成，不启动替代写入 |
| 准备阶段取消或业务先于取消完成 | 停止后续下发；原业务成功/失败仍按实际记录，不伪造已取消 |
| 取消先返回未找到，原提交随后被接纳 | 本地取消意图保持，查询原任务并补发取消，不将第一次未找到当完成 |
| 已证实接纳前失败后服务返回新 READY 请求 | 沿原 UUID 保留准备修订与原请求历史，只使用允许接续的新修订，不覆盖旧记录 |
| 归档提交或响应失败 | 恢复原 producer/operation，业务不重跑 |
| 首次归档尚未建立恢复材料就中断 | 保留原输入与身份，核对旧调用及存储后依归档合同接续；不假定 resume 总能独立恢复 |
| 读回目录已发布、响应丢失或已有路径冲突 | 原目录保留；同一版本读取到另一个新目录并核对，既有目录本身不构成成功收据 |
| 错误成果版本、缺文件或内容损坏 | 读回/核对拒绝，不进入接受决定 |
| 另一任务的完整合法包或仅含主机检查的包 | 即使包内校验通过，也不能成为本次 workspace 修改的成果 |
| 验证修改了其他源码、最终补丁不同或相关证明缺失 | 保留验证环境差异，不把单文件候选记为独立验证通过 |
| 旧候选决定迟到、读回后文件改变 | 不套用到新候选；按原版本与实际内容重新核对 |
| 测试通过但需求未满足 | 可以拒绝验收，保留原验证与拒绝理由 |
| 时间、输出或尝试预算耗尽，随后重启 | 停止新下发；未知提交仍占额度，重启不清零，保留有界查询与取消能力 |
| 已完成任务再次查询 | 返回原结果，不新增业务或成果版本 |
| 知识未配置、无匹配或查询失败 | 三种结果分开，按预先声明的可选/必需属性处理，不伪造知识查询成功 |
| 学习候选发送失败或重复发送 | 保留候选与来源，原 ID 接续；不改写生产结果、不自动准入为知识 |

本地替身用于可控故障注入；安装态真实链路验证实际集成。两类结果分别记录。仅文档修改时检查链接、术语与已核对的源码边界，不重跑无关仓库全量测试。
